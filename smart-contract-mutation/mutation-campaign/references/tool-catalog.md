## Safe project-local installation recipes

Use existing installed tools read-only when suitable. When missing, record official source URL, exact version/tag, download SHA256 and install argv in the campaign environment. Verify release checksums where published; a computed checksum alone does not authenticate a download. Never run a home-writing curl installer, global npm/pip install or administrator command. Do not auto-install WSL.

```powershell
python -m venv <project>/.mutation/tools/python
<project>/.mutation/tools/python/Scripts/python.exe -m pip install slither-analyzer==<verified-version>
<project>/.mutation/tools/python/Scripts/python.exe -m pip install universalmutator==<verified-version>
npm install --prefix <project>/.mutation/tools/muton --save-exact @trailofbits/muton@<verified-version>
node <project>/.mutation/tools/muton/node_modules/@trailofbits/muton/run-muton.js --help
```

On Linux use `bin/python` in the venv. Set project-local HOME/XDG/TEMP/npm/pip/compiler caches **before** installation. Foundry/Mewt/Acton and solc binaries may be extracted from official release assets inside `.mutation/tools/`; record asset OS/architecture and checksum. New dependencies of the tested project belong in its worktree via lockfile-aware `npm ci` or the project's documented equivalent. A shell wrapper must not hide untracked external installation effects.

Version/help probes: `forge --version` / `forge test --help`; `slither-mutate --help`; `mewt --version` / `mewt run --help`; `muton --version` / `muton run --help`; `acton --version` / `acton test --help`; `mutate --help` plus installed Python package/rule metadata. The controller then performs baseline, applied-source canary and native calibration. A successful help call is not executable support evidence.
