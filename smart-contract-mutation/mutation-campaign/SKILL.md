# Mutation campaigns

Improve the sensitivity of tests to specified behavior. A score is evidence about a selected test/operator population, not a security guarantee. Complete selected calibrated runs and account for every survivor; 100% is unnecessary.

Act as the coordinator. Assign work by capability and artifact: project/tool research, environment setup, tool execution, survivor analysis, independent verification. Give each agent a bounded question, source/evidence paths, allowed writes, expected output and stop conditions. Use available native agents or the CLI runtime adapter, without prescribing models or product role names. Dependent work is sequential. Parallel tools/writers require different Git worktrees and separate caches; the runner computes a conservative CPU/RAM budget including internal workers.

Read [protocol.md](references/protocol.md) for the runnable scope format and commands, [tool-catalog.md](references/tool-catalog.md) when choosing tools, [analysis.md](references/analysis.md) for interpretation, and [runtimes.md](references/runtimes.md) before a background handoff. Fork projects also require [forks.md](references/forks.md).

1. Use `$mutation-project-scout` to discover source, specs, tests, network pins and installed tool capabilities. Preserve the current checkout. Include relevant dirty/untracked files and explicitly required ignored test inputs. No HEAD substitution.
2. Use `$mutation-environment` to prepare project-local dependencies. Write a source-bound scope manifest with targets/exclusions/shared dependencies, exact build/tests, operators/seed/sample limits, tool rationale, timeouts and worker/RAM estimates. Inspect commands before execution: tests only, no broadcasting/deployment/push. Add another tool only for distinct operators/languages or useful independent corroboration.
3. Initialize with `python <this-skill>/scripts/campaign.py init --project <project> --scope <scope.json>`. State lives under `.mutation/<id>/`, lanes under `.worktree/mutation-<id>/`. Existing reserved paths, links, submodules and changed source during capture fail closed. Original source/index/refs remain unchanged.
4. For Foundry, first probe and calibrate `forge test --mutate`. On Windows, the current runner allows help/version probes but unconditionally blocks direct Forge workloads; the tested Forge 1.8.6 Windows binary wrote to the user `.foundry` cache despite project HOME variables. Prefer an already-installed WSL2 and run the controller there with campaign-local HOME/TMP. Do not use arbitrary Windows wrappers to bypass the guard: their effective cache paths are unchecked, and no wrapper-based Windows Forge route is supported. Linux/WSL wrappers require a separate environment-scout check of their effective cache path. Record an unavailable/configuration restriction before selecting a fallback. Use `$evm-mut` or `$ton-mut` for engine-specific interpretation. Universal Mutator uses the canonical sibling `$web3-universalmutator` guidance; the campaign runner compiles/tests generated files separately.
5. Run the nonempty baseline. Preserve its first failure; investigate/repair only proven configuration/test defects in the lane, then use `campaign.py successor` so the failed baseline, exact command logs, before/after repair and frozen specification stay linked. Never weaken assertions just to pass. Applied-source canary must fail the intended assertion after fresh compilation, and a real native generation run must demonstrate kills before full execution. All-survive calibration, stale output and vacuous invariants require diagnosis, not extra tests by guesswork.
6. For long work, bind a runtime session, start `run --background`, record PID/checkpoint and **end the active turn**. Setup and calibration are bounded; full native campaigns have no overall elapsed-time cap and stop through per-mutant timeouts, observed progress/idle detection or cancellation. The detached supervisor continues and resumes the exact saved CLI session with a hash-bound proposal for every survivor. Check its outbox receipt; a launched process is not successful delivery. `resume` recovers interrupted tool work; `deliver` retries event delivery without rerunning tools. Do not keep an agent polling for hours.
7. Use `$mutation-survivors` for every original survivor ID, grouped only with evidence. Establish expected behavior before adding tests in a lane. Replay the affected mutant and original baseline, retaining old results and new-test lineage. A suspected original-contract defect gets a reproducer and separate proposed patch; original production files require a human decision.
8. Obtain `$mutation-verifier` in a fresh independent session over the current evidence bundle. `verify` records the actual invocation; `finish` rejects missing, self-authored or stale review. Report blocked/unverified routes explicitly and continue independent work.

No MCP/connector, global install or specific model is required. Project commands execute trusted local code; this runner is not a network sandbox. RPC helpers expose reads only, and scope reviewers must reject broadcast commands. Secrets belong in environment variables, never scope argv or reports.
