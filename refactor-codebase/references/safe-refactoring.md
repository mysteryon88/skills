# Безопасный рефакторинг: поведение, тесты и проверка

## Characterization tests

Для legacy-кода без тестов зафиксируй фактическое поведение перед изменением:
обычные входы; пустые/null/zero/false значения; границы; ошибки; повторные вызовы;
порядок side effects; состояние до/после. Наблюдаемое поведение не обязательно
правильное. Подозрительное поведение помечай `known-bug` или `unresolved`.

Стабилизируй время, RNG, network, filesystem и БД. Не подменяй expected values
предположениями: получай их реальным запуском или из утверждённого контракта.

## Contract checklist

Перед перемещением/переименованием проверь callers, imports, exports, re-exports,
DI bindings, reflection, decorators, plugin registries, routes, schemas, serializers,
API clients, events, queues, job names, CLI, environment keys, migrations, DB columns,
error types/codes/messages, authorization, transaction/concurrency semantics и docs.

Поиск идентификатора не всегда находит потребителей enum/state/role. Ищи также
switch/match, lookup tables, validators, serializers, fixtures, translations и fallbacks.

## Expand-Contract

1. Добавь новый интерфейс/путь, сохрани старый.
2. Переведи consumers постепенно.
3. Проверь отсутствие старых callers.
4. Сохрани старый путь, если внешние или динамические потребители не проверены.
   Удаляй только при наличии требуемого явного разрешения и соблюдении правил проекта.

## Проверки

Определи команды из репозитория. Типичный набор: unit/integration/e2e tests,
typecheck/compiler, lint/static analysis, build, migration/schema validation,
smoke tests и performance checks для hot paths. Сначала изучи scripts/CI/docs.
Перед запуском оцени побочные эффекты; в AUDIT не запускай записывающие команды.
Временные файлы и сборки размещай в `<project>/.tmp/`. После разрешённых
auto-fixers повторно запускай доступные typecheck и тесты. Для долгих проверок
заранее установи timeout и способ установить владельца/PID, границы и завершение
своего дерева процессов. Проверяй его после успеха, ошибки и timeout; если нет
подтверждения завершения всех потомков, прямо укажи ограничение. Чужие процессы
и повторно использованные PID не останавливай.

Не подгоняй проверки: не удаляй упавшие тесты, не меняй expected result ради
зелёного статуса, не ослабляй lint/type/security rules, не заявляй о запуске
проверки, которая не выполнялась. Тесты должны проверять поведение через
публичный интерфейс, где это уместно.

## Rollback

Каждый крупный этап должен быть ограничен и обратим. При неудаче локализуй
собственные изменения, откати только их безопасным способом, сохрани пользовательские
изменения, запиши причину и не продолжай зависимые этапы на сломанном состоянии.

## Git и публикация

Не коммить, не пушь, не открывай PR и не сливай ветки без разрешения пользователя.
Соблюдай иерархию действующих инструкций и более строгие ограничения. Если правило
проекта требует коммит, а полномочия или конфликт указаний неясны, спроси до него.
Если разрешение дано, соблюдай branch protection и обязательные проверки.
Сверяй целевой checkout и относящиеся к задаче локальные refs/worktrees без
автоматического fetch или переключения; указание пользователя на конкретную ветку
не заменяй предположением о «главной» ветке.

## Передача на независимое ревью

Если оно запрошено/требуется и разрешено, передай базовый commit, diff, новые
untracked файлы проверяемой правки, точные результаты проверок и доступные пути.
Не передавай несвязанные пользовательские файлы, секреты или приватные конфигурации.
Проверь кодировку и доступность материалов. Необходимое evidence, которое
недоступно или нельзя безопасно передать, ограничивает ревью. Этот чек-лист не
разрешает делегирование сам по себе.

## Чек-лист итогового diff

- [ ] Нет несвязанных изменений.
- [ ] Все callers обновлены.
- [ ] Старый код сохранён либо удалён после миграции consumers и требуемого разрешения.
- [ ] Нет новых циклических зависимостей.
- [ ] Дубли уменьшены без ложной абстракции.
- [ ] Новые модули имеют понятную ответственность и небольшой интерфейс.
- [ ] Конфигурация не стала глобальной свалкой.
- [ ] Поведение и контракты сохранены или изменения перечислены.
- [ ] Тесты/typecheck/lint/build проверены с точными результатами.
- [ ] Документация и пути обновлены при необходимости.
- [ ] Пользовательские незакоммиченные изменения сохранены.
